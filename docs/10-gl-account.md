# G/L 계정: SAP GUI와 RAP 연결

**G/L 계정은 특정 종류의 회계 거래를 기록하는 개별 계정**입니다. 로그인 계정이 아닙니다.

| 개념 | 역할 |
|---|---|
| 회사코드 | 어느 회사의 회계인지 구분 |
| 계정과목표 | 사용할 계정들의 목록과 구조 |
| G/L 계정 | 예금·매출·급여 등 특정 거래 종류를 기록 |
| 총계정원장 | 계정별 거래와 잔액을 관리하는 중심 장부 |

## 1. 거래 예시

당월 급여를 처음 비용으로 기록하고 예금으로 지급하는 단순 예시입니다.

| 차변 | 대변 |
|---|---|
| 급여 100만 원 | 예금 100만 원 |

급여 계정에는 비용 증가, 예금 계정에는 자산 감소가 기록됩니다. 여러 전표의 항목이 계정별로 쌓입니다.

**계정 마스터는 기본 설정, 전표 항목은 실제 거래 기록**입니다.

## 2. 계정 마스터 구조

| 수준 | 주요 정보 |
|---|---|
| 계정과목표 수준 | 계정번호·명칭·계정그룹·계정 유형 |
| 회사코드 수준 | 계정 통화·세금 범주·조정계정 여부·미결항목 관리·필드상태그룹 |

계정과목표에 존재해도 회사코드별 데이터가 없으면 해당 회사에서 사용할 수 없는 상황이 발생할 수 있습니다.

| 설정 | 의미 |
|---|---|
| 조정계정 | 고객·공급업체 등의 보조원장 거래를 GL에 연결 |
| 미결항목 관리 | 관련 항목과 정산되었는지 추적. 모든 계정에 적용하는 것은 아님 |
| 필드상태그룹 | 전표 입력 필드를 필수·선택·숨김 등으로 제어 |
| 전기 차단 | 계정에 대한 전기 제한 |

## 3. 재무제표와 연결

| 계정 분류 | 예시 | 표시 |
|---|---|---|
| 재무상태표 계정 | 예금·채권·채무·자본금 | 특정 시점의 자산·부채·자본 |
| 손익계산서 계정 | 매출·급여·임차료 | 일정 기간의 수익·비용 |

연말 잔액 이월에서 재무상태표 계정 잔액은 다음 연도 기초 잔액으로 이어지고 손익 계정의 결과는 이익잉여금 등 관련 계정으로 연결됩니다. 모든 손익 계정을 사용자가 수동 분개로 정리해야 한다는 뜻은 아닙니다.

## 4. SAP GUI

대표적으로 FS00에서 계정 마스터를 관리합니다. 버전·권한에 따라 기능을 확인합니다.

1. 계정명과 회계 성격 확인.
2. 계정과목표 공통 정보 확인.
3. 회사코드별 데이터 확인.
4. 통화·세금·필수 필드·미결항목 관리·차단 설정 확인.

FS00은 마스터 관리 목적이며 거래 항목·잔액 조회와 구분합니다.

## 5. RAP CDS와 필드

| 표준 CDS | 목적 |
|---|---|
| I_GLAccountInChartOfAccounts | 계정과목표 수준 계정 정보 조회 |
| I_GLAcctInChtOfAcctsStdVH | G/L 계정 값 도움말 |

표준 CDS의 필드·공개 상태·지원 용도는 실제 시스템에서 확인합니다.

사용자 정의 요청 항목의 필드 예시:

| 필드 | 역할 |
|---|---|
| CompanyCode | 어느 회사의 요청인가? |
| ChartOfAccounts | 어느 계정 체계인가? |
| GLAccount | 어떤 계정인가? |
| Amount | 얼마인가? |
| Currency | 어떤 통화인가? |

이 필드들이 하나의 표준 CDS에 모두 있다는 뜻은 아닙니다.

## 6. Association 예시

```abap
association [0..1] to I_GLAccountInChartOfAccounts
  as _GLAccount
  on  $projection.ChartOfAccounts = _GLAccount.ChartOfAccounts
  and $projection.GLAccount      = _GLAccount.GLAccount
```

전체 CDS가 아닌 관계 정의 부분입니다. 계정과목표와 계정번호를 모두 비교해야 합니다.

- 계정번호만 비교하면 다른 계정과목표의 같은 번호와 잘못 연결될 수 있습니다.
- [0..1]은 대상이 없거나 최대 한 건이라는 관계 선언이며 실제 유일성에 맞게 설정합니다.
- Association은 존재 검증이나 회사코드별 전기 가능 여부를 자동 보장하지 않습니다.

## 7. RAP 검증과 표준 회계 연계

| 확인 | 목적 |
|---|---|
| 회사코드·계정과목표 일치 | 다른 계정 체계 선택 방지 |
| 회사코드별 계정 데이터 | 회사별 사용 가능 여부 |
| 전기 차단·업무상 허용 계정 | 사용 제한과 업무 규칙 |
| 통화·세금·필수 정보 | 거래 조건 충족 |
| 조회·변경 권한 | 데이터 및 업무 보호 |

적절한 값 도움말과 서버 검증을 구현하고 실제 FI 전기는 지원 표준 업무·API로 연결합니다. **요청 테이블에 계정번호를 저장한다고 GL에 전기되는 것은 아닙니다.**
